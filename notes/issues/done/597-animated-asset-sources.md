# `ralphy stock`: animated, sticker and icon sources

> **Status:** done — 2026-10-30 (`--kind animation|sticker|icon`; five new file-scoped connectors: `noto-emoji`, `fluent-emoji`, `iconify`, `pixabay`, and the import-only `pinterest`; Commons serves `--kind animation`; animations land in `artifacts/animations/`, stickers and icons in `artifacts/images/`; Pinterest pins are reference only in `stock credits`; LottieFiles skipped, no documented keyless API; verified with live keyless searches and pulls on Noto, Fluent, Iconify and Commons)
> **Filed:** 2026-10-30
> **Folder:** issues
> **Severity:** medium
> **Category:** assets / editor / CLI / connectors

## Context

`ralphy stock` (#596) collects logos, photos, b-roll, SFX and music beds. The owner's montage demos built from those came out flat: every overlay is a still photo or a single-color logo. Short-form edits lean on motion and on cut-out objects: animated emoji and stickers, Lottie, GIF / WebP / WebM micro-animations, transparent stickers, icons, and better photos. The owner also collects references on Pinterest and wants those boards importable.

## What

- New kinds for `stock search --kind` and `stock pull`:
  - `animation`: Lottie JSON, animated WebP / GIF, short WebM. Pulled into `artifacts/animations/`.
  - `sticker`: transparent PNG / SVG objects and emoji. Pulled into `artifacts/images/`.
  - `icon`: SVG icons. Pulled into `artifacts/images/`.
- `noto-emoji`: Google Noto Animated Emoji (Lottie, 512 px WebP / GIF, static SVG / PNG), keyless, searched through the project's own index.
- `fluent-emoji`: Microsoft Fluent UI Emoji (3D PNG, flat SVG, MIT) from a pinned commit on jsDelivr; the keyword index is built once from the per-emoji `metadata.json` files and cached under `.ralphy/cache/stock/`.
- `iconify`: the keyless Iconify API (search, SVG). The license comes per icon set from the collections endpoint; GPL / OFL / unknown fail `--license commercial`, CC BY-SA fails `open`. Animated sets (`line-md`, `svg-spinners`, ...) serve `--kind animation`.
- `commons` gains `--kind animation`: animated GIF, animated WebP and WebM of at most 20 s.
- `pixabay`: photos, illustrations, vectors and video under the Pixabay Content License; free `PIXABAY_API_KEY` read only through `cli/lib/providers/credentials.ts`, skipped with a note when missing.
- `pinterest`: URL import only, no search. `ralphy stock pull pinterest:<pin-or-board-url> --project <id>` reads pin or board metadata with the local `yt-dlp -J` (no cookies, login, proxies or CAPTCHA handling), caps pins per board (`--max`, default 30) and pauses between downloads. The license is unknown ("rights belong to the pin's creator; reference only"), so such items fail `commercial` and `open` and need `--license any`; `stock credits` lists them under a separate "reference only, not cleared for publishing" heading. The help states that Pinterest's terms restrict automated access.
- LottieFiles only if a documented, keyless public API exists; otherwise skipped with the reason recorded here.

## Scope / acceptance

- Each source is its own connector file under `cli/lib/providers/` with file-scoped hosts and an injectable fetch (AGENTS.md invariant #1); `PIXABAY_API_KEY` is descriptor-owned. `tests/unit/agents-md-invariants.test.ts`, `credential-reader-boundaries.test.ts` and `provider-credentials.test.ts` extended.
- Unit tests per new connector (parsing, license mapping, kind filtering) with fixtures under `tests/fixtures/stock/`, zero network.
- Integration test: pulling an `animation` (Lottie JSON) and a `sticker` into a temp project (placement, provenance, no overwrite) and the credits sections, including reference-only.
- Editor skill reference, help text, verb shapes and `docs/cli-surface.generated.md` updated; lints and unit tests green.

## Resolution

- Kinds: `cli/lib/stock/types.ts` adds `animation | sticker | icon`. Pull folders: animation -> `artifacts/animations/` (created on the first pull; not added to the `ralphy new` scaffold in `paths.ts ARTIFACT_KINDS`), sticker / icon -> `artifacts/images/`. An animation's Artifact kind follows the sniffed bytes: Lottie JSON (an object with `layers`, `fr`, `op`) is `data`, WebM `video`, GIF / WebP / SVG `image`. Default sources: animation `noto-emoji, iconify, commons`; sticker `fluent-emoji, noto-emoji, pixabay`; icon `iconify`; image and video add `pixabay`. Stickers and icons ignore `--orientation`.
- Connector contract additions (all optional): `idPattern` / `idHint` (a malformed id is refused before any request), `searchable: false` (import-only), `referenceOnly` (the pull needs `--license any` before any request), `requiredBinary` (missing -> `E_DEP_MISSING`), `coldStartTimeoutMs` (a longer deadline while a source builds its cached index), `expand` (a collection id becomes its item ids), `pullPauseMs`. Shared on-disk cache `cli/lib/stock/cache.ts` under `.ralphy/cache/stock/` (`stockCacheDir()`); keys never hold an API key.
- `noto-emoji` (`cli/lib/providers/noto-emoji.ts`). Index: `https://googlefonts.github.io/noto-emoji-animation/data/api.json`, the file the project's own site loads (881 emoji on 2026-10-30: name, codepoint, tags, categories, popularity; its `host` and `asset_url_pattern` fields are empty), cached for a day. Asset pattern, read from the site's app bundle: `https://fonts.gstatic.com/s/e/notoemoji/latest/<codepoint>/{lottie.json,512.webp,512.gif,512.avif,emoji.svg}`; `512.png` is also served (HTTP 200, checked) though the animated app does not link it. License: the site's FAQ ("Can I use these animated assets commercially ...") says Animated Noto Emoji is licensed under CC BY 4.0 and links the CC BY 4.0 legal code; recorded as CC BY 4.0, author Google, for every format. The static Noto Emoji artwork is Apache 2.0 in `googlefonts/noto-emoji` (its README), noted on sticker candidates. The `googlefonts/noto-emoji-animation` repository itself is not public (GitHub API 404), so the site is the authority. Ids `noto-emoji:<lottie|webp|gif|svg|png>:<codepoint>`; a search returns Lottie (animation) or SVG (sticker) and lists the other formats in `notes` / `extra`.
- `fluent-emoji` (`cli/lib/providers/fluent-emoji.ts`), pinned to `microsoft/fluentui-emoji@1ffb34c752ecf5d402f04cfb4b392c77f57c54bc` (2026-08-24, head of `main`). License: MIT (repository LICENSE at the pin, "Copyright (c) Microsoft Corporation"; GitHub reports MIT). Deviation from the brief: jsDelivr refuses the package listing for this repository (HTTP 403 "Package size exceeded the configured limit of 50 MB", also for directory listings), so the file list comes from one keyless GitHub git-trees request at the pin (27,127 entries, not truncated); the 1,595 `metadata.json` files come from jsDelivr (concurrency 16). The first search took about 45 s end to end and gets a 120 s cold-start deadline; the index (about 450 KB) is cached per pin and only when every metadata file loaded. Skin-tone emoji use the `Default` tone. 3D PNGs are 256 x 256 RGBA. Ids `fluent-emoji:<3d|flat>:<ascii-slug of the folder name>`.
- `iconify` (`cli/lib/providers/iconify.ts`): `api.iconify.design/search` (minimum `limit` 32), `/collections` (255 sets on 2026-10-30, cached for a day), `/<set>.json?icons=<name>` for lookup, SVG `/<set>/<name>.svg?height=auto` (dimensions from the viewBox instead of `1em`). `spdxLicense()` in `cli/lib/stock/license.ts` maps the per-set SPDX id: MIT / ISC / Apache / BSD / zlib (notice required), CC0 / Unlicense / 0BSD (none), CC BY* via the CC flags, MPL ShareAlike, GPL-family and OFL not cleared for commercial use (software / font licenses whose terms for artwork in a video are unclear), anything else unknown. Animated sets: those tagged "Contains Animations" (line-md, svg-spinners, meteocons), passed as `prefixes=` for `--kind animation`, with `iconify:animation:<set>:<name>` ids.
- `commons` animations: three `filemime:` searches (CirrusSearch takes one `filemime:` per query; `OR` returns nothing) with `metadata` in `viprop`; kept: GIF `frameCount > 1`, WebP `animated: true`, WebM `duration <= 20` (the WebM query adds `filesize:<30000` KB); ids `commons:animation:File:<name>`; the plain id of the same file still resolves as an image.
- `pixabay` (`cli/lib/providers/pixabay.ts`): `PIXABAY_API_KEY` via the new `pixabay` descriptor in `credentials.ts`, sent as the documented `key` query parameter; responses cached 24 h as the API terms require (cache key without the key); `--kind sticker` asks `image_type=vector`; video takes the largest file at most 1080 lines. Bad key (HTTP 400 "API key", or 401 / 403) maps to `E_PROVIDER_AUTH`. Fixture-tested only (no key on the machine).
- `pinterest` (`cli/lib/providers/pinterest.ts`): `stock pull pinterest:<pin-or-board-url>` (pins on any `pinterest.<tld>`, boards `/<user>/<board>/`, `pin.it` short links) runs `yt-dlp --ignore-config -J --ignore-no-formats-error` through the logged-out runner of `cli/lib/trends/sources/ytdlp.ts` (refuses cookies, login, netrc and proxy flags); a board adds `--playlist-end <max>`, `--max` defaults to 30 (at most 200), and `stock pull` pauses 2 s between downloads from the source. yt-dlp's Pinterest extractor is video-oriented: an image pin has no formats, so `--ignore-no-formats-error` is needed and the original image is the largest `i.pinimg.com` thumbnail (`/originals/` preferred); video pins download through yt-dlp itself (`-f "b[ext=mp4][height<=1080]/b[height<=1080]/b"`, scratch outside the Project). Pins that embed another site's video (another `extractor_key`) are skipped. License `unknown (rights belong to the pin's creator; reference only)`, `extra.referenceOnly: true`; `stock credits` lists such items (and any item with an unknown license) under "Reference only, not cleared for publishing:". The help states that Pinterest's terms restrict automated access. No live Pinterest pull was run (no pin URL from Pinterest's own help or press pages at hand); the yt-dlp JSON parsing is fixture-tested against the extractor's shape (`yt_dlp/extractor/pinterest.py`, 2026.08.19).
- LottieFiles: skipped. The only documented programmatic access is the hosted LottieFiles MCP server (docs.lottiefiles.com/en/platform/mcp), which signs in through a browser with a LottieFiles account and runs GraphQL "with your account's permissions"; no documented keyless public API was found, and the brief rules out scraping the site.
- Live check (2026-10-30, keyless, temp root): `stock search dog --kind animation --source noto-emoji` (3: `noto-emoji:lottie:1f415` Dog, guide dog, service dog; CC BY 4.0), `stock search cat --kind sticker --source fluent-emoji` (cold start about 45 s, then cached; `fluent-emoji:3d:cat`, cat face, black cat, weary cat; MIT), `stock search pet --kind sticker --source fluent-emoji` (keywords: cat, dog, rabbit), `stock search paw --kind icon --source iconify` (32 returned: `iconify:mdi:paw` Apache 2.0, solar CC BY 4.0, ...), `stock search loading --kind animation --source iconify` (`iconify:animation:line-md:loading-loop`, MIT), `stock search "dog running" --kind animation --source commons` (1: `commons:animation:File:Dog_galloping.gif`, public domain; `dog` alone returned 18 GIF / WebM), `stock search heart --kind animation` (all three default sources answered). A live pull of `noto-emoji:lottie:1f415`, `fluent-emoji:3d:cat`, `iconify:animation:line-md:heart` and `commons:animation:File:Dog_galloping.gif` wrote `artifacts/animations/*.json|svg|gif` and `artifacts/images/*.png` with provenance at $0, and `stock credits` listed them.
- Tests: `tests/unit/stock-animated-sources.test.ts` (fixtures `noto-emoji-index.json`, `fluent-tree.json`, `fluent-metadata.json`, `iconify-collections.json`, `iconify-search-star.json`, `commons-search-animation.json` trimmed from live captures; `pixabay-*.json` and `pinterest-ytdlp.json` from the documented shapes), `tests/integration/stock-pull-597.test.ts` (Lottie and sticker placement, provenance, no overwrite, dry run, a Pinterest board with `--max` and reference-only credits, CLI validation), invariant tests for each new host family and `PIXABAY_API_KEY`. Existing #596 tests that used `pinterest:123` as an unknown prefix now use `flickr:123`.
