Every video model on OpenRouter expects a slightly different prompt shape — Kling brackets dialogue, Veo wants a 7-part skeleton, Luma needs a trailing reinforcer, Sora prefers camera-as-perspective syntax. The adapter layer in `cli/lib/providers/prompt-adapter/` handles these differences from a single normalized input, so you never write the model-specific syntax by hand. This page documents what each adapter does so you can pick the right model in 30 seconds and know what's happening to your text on the way out.

## The normalized prompt

Every adapter consumes the same shape from `cli/lib/providers/prompt-adapter/types.ts`:

```ts
type NormalizedPrompt = {
  subject: string;       // identity tokens, who/what is in frame
  action: string;        // verb phrase
  setting: string;       // where + when
  camera: string;        // one-line camera direction
  lighting: string;      // direction + temperature + softness
  style: string;         // register / film stock / aesthetic
  dialogue?: string;     // one line; adapter syntaxes it
  dialogueTone?: string; // "deadpan", "hyped", "neutral"
  motion?: string;       // "slow push-in", "static handheld"
  gesture?: Gesture;     // finite enum from cli/lib/schemas/gestures.ts
  durationS?: number;
  aspectRatio?: "9:16" | "16:9" | "1:1";
  notes?: string;        // free-text "director intent" escape hatch
};
```

The dispatcher (`cli/lib/providers/prompt-adapter/index.ts:26`) routes by model-id prefix: `kwaivgi/kling-*` → Kling adapter, `google/veo-*` → Veo adapter, etc. Unknown models fall back to the Pika-style generic.

You don't write this shape directly — the art-director / scenarist layer builds it from your brief, then calls `shapePrompt(modelId, input)`. The pages below describe what each adapter emits.

## Kling — `kwaivgi/kling-v3.0-pro`, `kling-v3.0-std`, `kling-video-o1`

**Best at:** Default narrative i2v, character consistency, holding a keyframe, talking-head with native EN lip-sync. The default for any photoreal-human i2v per `MODELS.md`.

**Shape emitted by `kling.ts`:**

```text
Scene: <setting>.
Character: <subject>.
Shot: <camera>. Lighting: <lighting>. Style: <style>.
Motion: <motion>; <gesture>; <action>.
Dialogue: [<Speaker>, <tone>]: "<dialogue>"
Progression: <duration>s clip, <aspect>, no background music, SFX only.
Director notes: <notes>.
```

The adapter derives the bracketed speaker tag from the first comma-clause of `subject`, capped at 32 chars (`kling.ts:18-20`). It auto-appends `no background music, SFX only` to the Progression block (`kling.ts:53`) because Kling otherwise auto-bakes ambient piano.

**Example output:**

```text
Scene: home office, late morning. Character: Alex, 32, dark brown hair short
beard navy hoodie. Shot: selfie 35mm, eye-level, handheld with slight sway.
Lighting: soft window light from screen-left. Style: Sony FX3 documentary
register, naturalistic NOT glossy. Motion: lean-in, eyes locked on lens;
slight eyebrow raise on punch word. Dialogue: [Alex, deadpan]: "I'm not going
to sugarcoat this." Progression: 5s clip, 9:16, no background music, SFX only.
```

**Gotchas:**

- **2500-char prompt cap.** OpenRouter returns 400 after the round-trip if exceeded. Trim atmosphere first; voice-tag, no-music, on-camera-EN clauses are load-bearing.
- **`--audio` is English-only.** Russian / Korean / Spanish all slip accent and drift voice age. Default off; only enable for EN.
- **"Wide" prompts get rotated inside the 9:16 container.** Phrases like *"wide overhead cityscape"* bias the model toward landscape composition inside the portrait frame. Anchor with `--first-frame` and rewrite with explicit vertical wording per `MODELS.md` Lesson 1.
- **`--resolution 720p` is silently upgraded to 1080p.** Treat resolution as a soft hint; let downstream Remotion crop/scale.

## Veo — `google/veo-3.1`, `veo-3.1-fast`, `veo-3.1-lite`

**Best at:** Talking-head with native lip-sync (English / Chinese), wide cinematic establishing, 4K master (via `veo-3.1-fast`). Maximum duration 8s — for longer clips, Kling is the path.

**Shape emitted by `veo.ts`:** A strict 7-part skeleton, in this order — Shot framing & motion, Style, Lighting, Character, Location, Action, Dialogue.

```text
Shot: <camera>, <motion>.
Style: <style>.
Lighting: <lighting>.
Character: <subject>.
Location: <setting>.
Action: <action>; <gesture>.
Dialogue (<tone>): "<dialogue>"
Director notes: <notes>.
```

**Example output:**

```text
Shot: selfie 35mm, eye-level, slight handheld. Style: naturalistic, Kodak
Portra register. Lighting: window light screen-left, ambient indoor.
Character: Alex, 32, dark brown hair beard navy hoodie. Location: home office,
morning. Action: leans in slightly, holds eye contact; slight eyebrow raise.
Dialogue (deadpan): "I had to rebuild it from scratch."
```

**Gotchas:**

- **Veo lip-syncs natively.** If you supply VO in the prompt, expect mouth shapes to track. Don't *also* overlay ElevenLabs — you'll get a double-mouth artifact.
- **8s duration cap.** For 15s narrative you need Kling. KBO postmortem hit this.
- **`veo-3.1-fast` is the only catalog model with 4K.** Use for hero pieces; per-clip cost ~$0.14 (verified).
- **Skip meta-commentary.** Veo reads `Shot:` as the cue. Don't write "the camera shows…" — adapters do not, but if you're hand-editing, don't either.

## Luma — `luma-ray-2`, `luma-ray-3`

**Best at:** Slow narrative B-roll, surreal/conceptual imagery, dreamy product loops. Responds to long descriptive prose better than tagged sections.

**Shape emitted by `luma.ts`:** Comma-delimited prose plus a trailing reinforcer sentence that repeats the subject plus the first style noun. The reinforcer counteracts Luma's tendency to drift mid-clip.

```text
<subject>, <action>, in <setting>, shot <camera>, lit by <lighting>,
styled <style>, <gesture>, <motion>, speaks in a <tone> tone: "<dialogue>".
The <subject> stays the focus, <styleNoun> register held throughout.
```

The `firstNoun()` helper (`luma.ts:13-22`) picks the first non-stopword token >3 chars from `style` for the reinforcer.

**Example output:**

```text
Maya, 26, light brown skin freckled cheeks navy sweater, telling a story at
a kitchen counter, in cozy home kitchen, shot selfie 35mm at eye-level with
slight handheld sway, lit by warm window light from screen-right, styled
Kodak Portra 400 naturalistic NOT glossy, slight smile flickers as she speaks.
The Maya stays the focus, Kodak register held throughout.
```

**Gotchas:**

- **No bracket syntax.** Luma reads `[X, Y]:` as literal text, not a directive. The adapter avoids brackets entirely.
- **No `Shot:` / `Scene:` tags.** Use natural prose. The adapter does this; if hand-editing, do the same.
- **Off OpenRouter catalog.** Per `MODELS.md`, `luma-dream-machine` was dropped — worse than Kling at the same price. The adapter ships for future re-additions and direct API usage.

## Runway — `runway/gen-4`, `runway/gen-5`

**Best at:** Two-character cinematic dialogue scenes, motion-graphic overlays, product rotations. Splits refs into `subjectReference[]` vs `styleReference[]`.

**Shape emitted by `runway.ts`:**

```text
Subject: <subject>.
Action: <action>.
Setting: <setting>.
Style: <style>; <camera>; <lighting>.
Motion: <motion>.
Gesture: <gestureProse>.
Dialogue (<tone>): "<dialogue>".
Notes: <notes>.
Temporal consistency: identity locked across the clip.
```

The trailing `Temporal consistency: identity locked across the clip` line is appended by the adapter (`runway.ts:36`) — Runway responds to the explicit reminder.

**Example output:**

```text
Subject: Alex, 32, dark brown hair beard navy hoodie. Action: speaks
deliberately, occasional eyebrow raise. Setting: home office, late afternoon.
Style: documentary realism, Sony FX3 register; selfie 35mm; soft window from
screen-left. Motion: micro-movements only, head stable. Dialogue (calm):
"I had to rebuild it from scratch." Temporal consistency: identity locked
across the clip.
```

**Gotchas:**

- **Refs are routed by role.** Don't dump everything into one ref slot — pass identity anchors as subject refs, aesthetic anchors as style refs.
- **Short clips work best.** ≤8s, single-subject focus. Long clips drift even with the temporal-consistency reminder.

## Pika — `pika-2`, `pika-labs/*`

**Best at:** TikTok meme cuts, animated character action, motion graphics. Fast iteration. Forgiving with flat prose.

**Shape emitted by `pika.ts`:** Flat comma-delimited list in fixed order. The dispatcher's **fallback adapter** for unknown model ids (`index.ts:53`) — broadest-applicable shape.

```text
<subject>, <action>, <setting>, <style>, <camera>, <lighting>,
<motion>, <gesture>, spoken <tone>: "<dialogue>"
```

**Example output:**

```text
a confused teenager in a hoodie, shrugs and looks off-camera, suburban
bedroom, TikTok native flat register, handheld 28mm front-cam, overhead LED
ceiling light, snap cut from neutral to confused, palm-open gesture,
spoken neutral: "wait what"
```

**Gotchas:**

- **Order matters.** Pika weights early tokens heavier — subject first, then action.
- **No `Shot:` / `Scene:` tags.** Flat prose only.
- **Dialogue is ambient text.** Don't expect strict lip-sync. For lip-sync, use Kling or Veo.

## Sora — `openai/sora-2`, `sora-2-pro`, `sora-turbo`

**Best at:** Physics-rich short scenes, POV / bodycam / drone perspectives, single declarative beats. Rewards tight noun-verb sentences.

**Shape emitted by `sora.ts`:** Short declarative sentences. The camera is rewritten as a **perspective noun** via `asPerspective()` (`sora.ts:12-25`) — `bodycam` → `bodycam perspective`, `selfie` → `selfie perspective`, `dolly` → `dolly perspective`.

```text
<perspectivized-camera>.
<subject> <action>.
<setting>.
<lighting>.
<style>.
<motion>.
<gesture>.
Voice (<tone>): "<dialogue>".
```

**Example output:**

```text
Bodycam perspective. A delivery courier in a yellow rain jacket walks fast
down a wet city sidewalk. Late evening, neon shop signs reflected in puddles.
Sodium streetlight overhead, cool blue rim from screen-left. Documentary
realism, slight motion blur. Steady forward stride with side-to-side bob.
Voice (urgent): "I'm almost there."
```

**Gotchas:**

- **No bracketed dialogue.** Adapter uses `Voice (tone): "line"`.
- **Avoid dense modifier stacks.** Each sentence does one job. The adapter enforces this by splitting into independent sentences.
- **Physics-rich nouns work best.** "Bodycam perspective," "drone perspective," "first-person POV perspective" — concrete, named, well-attested in the corpus.

## Seedance — `bytedance/seedance-2.0`, `seedance-2.0-fast`, `seedance-1-5-pro`

**Best at:** Sharp physics motion (parkour, sports, falling), the only path to 21:9 cinema aspect, multi-frame i2v on non-human anchors.

**Shape emitted by `seedance.ts`:** Motion-forward — the action verb leads, physics cues at the end.

```text
<motion>, <subject> <action> in <setting>, <camera>, <lighting>, <style>,
<gestureProse>, speaks (<tone>): "<dialogue>", <notes>
```

**Example output:**

```text
camera tracks subject through whip-pan, a parkour runner leaps across a
rooftop gap in pre-dawn city, low-angle wide 24mm handheld, harsh sun cresting
behind buildings, hyper-real commercial register with motion blur, palm-open
gesture mid-leap
```

**Gotchas:**

- **Privacy filter rejects photoreal-human anchors.** Returns `InputImageSensitiveContentDetected.PrivacyInformation` even when the human was itself AI-generated. Validated across tokyo / noski / venom postmortems. **Reserve seedance for cartoons, non-human anchors, landscapes, hands, abstract motion.** For photoreal humans, use Kling.
- **`--audio` unsafe outside English** — same failure mode as Kling and Veo.
- **Strongest at fast motion.** Use for the action beats in a multi-clip piece, not for talking-head.

## Hailuo — `minimax/hailuo-2.3`

**Best at:** Russian-prompt tolerance (rare among i2v models). 16:9 only. First-frame anchor only (no last-frame).

**Shape emitted by `hailuo.ts`:**

```text
<subject>, <setting>, <action>, <camera>, <lighting>, <style>,
<motion>, <gestureProse>, dialogue (<tone>): "<dialogue>"
```

Order is `subject, environment, action, camera` — different from Pika's `subject, action, setting`.

**Gotchas:**

- **16:9 only.** No 9:16, no 1:1. For TikTok-feed compositions, you'll need to letterbox into a 9:16 canvas downstream (the meme-header format).
- **First-frame only.** No last-frame anchor, so multi-frame i2v isn't an option. Use Kling or Seedance for that.
- **Tolerates Russian** directly in the prompt body — rare among i2v models. For RU brief without an EN translation step, this is the path.

## Picking the right model in 30 seconds

| You need | Pick | Reason |
|---|---|---|
| Default narrative i2v, photoreal human, character consistency | `kwaivgi/kling-v3.0-pro` | Only viable for photoreal-human i2v |
| English VO with native lip-sync, 5–15s | `kwaivgi/kling-v3.0-pro --audio` | Cheaper than ElevenLabs post-mix, better sync |
| English VO with native lip-sync, ≤8s | `google/veo-3.1` | Slightly better lip-sync; 8s ceiling |
| 4K master hero | `google/veo-3.1-fast` | Only 4K in the catalog |
| Sharp physics motion, sports, parkour | `bytedance/seedance-2.0` | Best motion physics; cinema 21:9 |
| 3:4 / 4:3 portrait magazine | `alibaba/wan-2.7` | Only model with these aspects |
| Russian prompt body, no EN translation step | `minimax/hailuo-2.3` | Tolerates RU directly; 16:9 only |
| Slow narrative B-roll, surreal product loop | Luma adapter (when on catalog) | Adapter ready for direct API use |
| TikTok meme cut, fast iteration, motion graphics | `pika-2` | Forgiving, cheap |
| POV / bodycam / drone establishing | `openai/sora-2` | Physics-rich perspectives |

Always cross-check against `MODELS.md` — pricing and catalog availability drift.

## CLI usage

The adapter runs automatically inside `ralphy generate video`. To see what the adapter would emit before submitting:

```bash
ralphy generate video --project <id> --slot scene-01-vid \
  --prompt "<your prose>" \
  --duration 5 \
  --model kwaivgi/kling-v3.0-pro \
  --dry-run
# → printed request body shows the shaped prompt the adapter built
```
