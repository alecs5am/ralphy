Templates are the reusable shape behind a video — a vibe-reference (full-stack production blueprint) or a vibe-style (prompt cookbook). They live in two locations that the CLI reads transparently, and the right way to discover one is `ralphy template suggest "<utterance>"`. Per [AGENTS.md invariant #10](https://github.com/alecs5am/ralphy/blob/main/AGENTS.md), always run `suggest` before reaching for a model — there's a good chance the format already exists.

## Two roots, one resolver

| Location | Layout | Audience | Storage |
|---|---|---|---|
| `templates/` (repo) | 5 category folders (`b2b-saas/`, `dtc-commerce/`, `creator-lifestyle/`, `entertainment-viral/`, `cinematic-narrative/`) | shipped on every clone | committed to git |
| `workspace/templates/` | flat | user-local, gitignored | per-checkout |

The loader resolves slugs across both roots. Workspace overrides repo on collision — letting you edit a published template locally without touching the repo copy.

Each location supports two on-disk layouts:

- **Flat:** `<root>/<id>.json`
- **Dir:** `<root>/<id>/template.json` + `TEMPLATE.md` + `composition.md` and friends

Dir-based templates are preferred — the LLM-readable doc (`TEMPLATE.md`) lives next to metadata.

## ralphy template suggest

The agent's discovery surface. Pass an utterance, get the top-N matching templates ranked by score.

```bash
ralphy template suggest "spring drop, deadpan founder, 15s"
ralphy template suggest "italian brainrot, 9:16, no music" --limit 5
```

Returns `{ matches: [{ slug, score, kind, summary, source }] }`. The scorer is a pure keyword matcher against frontmatter + body — no LLM call, fast and deterministic.

Full surface: [`/reference/cli/template`](/reference/cli/template).

## ralphy template list

```bash
ralphy template list
ralphy template list --kind vibe-style
ralphy template list --kind vibe-reference
ralphy template list --category entertainment-viral
ralphy template list --source repo
```

Returns `{ id, kind, source, name, summary }`. Two `kind` values ship today: `vibe-reference` (full-stack production templates with `composition.md` + reference example, 5 in repo) and `vibe-style` (prompt cookbooks with hooks + camera vocab + worked example prompts, 38 in repo).

## ralphy template show &lt;id&gt;

```bash
ralphy template show italian-brainrot
ralphy template show italian-brainrot --raw   # raw template.json
ralphy template show italian-brainrot --doc   # TEMPLATE.md only
```

The default form returns metadata plus a resolved doc summary. `--raw` and `--doc` are useful when piping into another tool.

## ralphy template use &lt;id&gt;

The verb that wires a template into a project. Validates required inputs (`brand`, `persona`, `refs`, …), pulls every required asset from the companion repo, copies them into the project tree, and writes `TEMPLATE_ORIGIN.md` so the project remembers its source.

```bash
ralphy template use italian-brainrot \
  --project demo-001 \
  --brand acme \
  --persona founder-monologue
```

When a required input is missing, the verb refuses with `E_TEMPLATE_INPUT_MISSING` and names the matching flag.

Full surface: [`/reference/cli/template`](/reference/cli/template).

## ralphy template create / register / delete

```bash
# Author a new template inline
ralphy template create \
  --id my-new-format \
  --kind vibe-style \
  --name "My new format" \
  --summary "..."

# Register an existing dir as a template
ralphy template register my-format --dir ./templates/my-format

# Remove
ralphy template delete my-new-format
```

`create` writes a flat `workspace/templates/<id>.json`; for richer templates, scaffold a dir under `workspace/templates/<id>/` manually and use `register` to add it to the registry. See [Template format](/advanced/template-format).

## Slug resolution

Given a slug, the resolver walks in this order:

1. `workspace/templates/<id>/template.json` (dir, workspace)
2. `workspace/templates/<id>.json` (flat, workspace)
3. `templates/<category>/<id>/template.json` (dir, repo, any category)
4. `templates/<id>/template.json` (dir, repo, uncategorized)
5. `templates/<id>.json` (flat, repo)

The first hit wins. Categorized repo layout (`templates/<category>/<id>/`) is the canonical shape post-2026-05; the flat fallbacks exist for back-compat.

## Manifests

Two repo manifests track the template surface:

- [`templates/CATEGORIES.md`](https://github.com/alecs5am/ralphy/blob/main/templates/CATEGORIES.md) — full slug-by-category roster
- [`templates/TOP.md`](https://github.com/alecs5am/ralphy/blob/main/templates/TOP.md) — Top-20 viral-2026 cross-category playlist

The agent reads `CATEGORIES.md` when it needs the full list and `TOP.md` when it's looking for a quick test-drive.

## Lint scripts

Two repo scripts catch template drift:

```bash
bun run lint:templates           # JSON schema + required inputs + slug rules
bun run lint:motion-graphics     # composition.md sanity (vibe-reference only)
```

CI runs both on every PR — see `scripts/lint-templates.ts` and `scripts/lint-motion-graphics.ts`.
