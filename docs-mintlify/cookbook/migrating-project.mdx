---
title: "Migrate an existing video"
description: "ralphy clone chains pull + analyze + blueprint into a workspace vibe-style template you can edit and register."
---

Lift the style of any existing TikTok / Reel / Short / YouTube into a reusable
Ralphy template. The `ralphy clone <url>` verb chains the four back-stage
research verbs into one front-stage call: `ref pull` (yt-dlp into the workspace),
`ref frames` (sample keyframes), `ref analyze` (vision LLM over the frames or
the full mp4), and `ref blueprint` (synthesize a composition spec). The output
is a `vibe-style` template under `workspace/templates/clone-<slug>/`. Edit the
composition, register, then promote to repo `templates/` if it earns its keep.

## Brief

> "I keep getting sent this TikTok from @somecreator. Take the visual style,
> make a Ralphy template from it. Don't copy the script — just the style."

## Stack

- **Verb:** `ralphy clone <url>` (or `ralphy clone <existing-ref-slug>` to skip the pull)
- **Vision analysis:** `google/gemini-2.5-flash` (default) for frame-by-frame, or `google/gemini-3.1-pro-preview` via `ref analyze-video` for full-mp4 register reading
- **Output:** `workspace/templates/clone-<slug>/template.yaml` + `composition.md`
- **Kind:** always `vibe-style` (clones are style lifts, not full-stack reference projects)
- **Cost:** ~$0.20 per clone (one yt-dlp pull is free, ~12 frames × $0.001 vision)
- **Runtime:** ~3 min per clone

## Walkthrough

<Steps>

<Step title="Run the clone verb">
The verb chains four steps internally. For a TikTok URL:

```bash
ralphy clone https://www.tiktok.com/@somecreator/video/7293... \
  --strict-look \
  --as-template clone-somecreator-style-001
# → 1. ref pull         — yt-dlp into workspace/references/<slug>/
# → 2. ref frames       — sample ~12 keyframes
# → 3. ref analyze      — gemini-2.5-flash over frames → analysis.json
# → 4. ref audio-describe — best-effort, skipped on --prompt-only
# → 5. ref blueprint    — synthesize composition.md from analysis + transcript
# → 6. template scaffold — write workspace/templates/clone-somecreator-style-001/
#                          with template.yaml + composition.md
```

Output:

```json
{
  "template_id": "clone-somecreator-style-001",
  "source_url": "https://www.tiktok.com/@somecreator/video/7293...",
  "source_slug": "tiktok-somecreator-7293",
  "blueprint_path": "workspace/references/tiktok-somecreator-7293/blueprint.md",
  "template_dir": "workspace/templates/clone-somecreator-style-001"
}
```

The `--strict-look` flag tells the analyzer to mirror palette / grading / hook
composition in the blueprint, not just describe them abstractly. Use it when
the brief is "copy the style", not "use this as one inspiration among many".
</Step>

<Step title="For video-URL register reading, use ref analyze-video">
The default `ref analyze` reads ~12 frames with `gemini-2.5-flash` — fast and
cheap, but it sees stills. For style work that depends on motion timing,
register, or temporal pacing (the "feel" of the cut), use `ref analyze-video`
which sends the full mp4 to `gemini-3.1-pro-preview`.

```bash
ralphy ref analyze-video tiktok-somecreator-7293 \
  --prompt-file workspace/prompts/style-extraction.md
# → writes workspace/references/tiktok-somecreator-7293/video-analysis.md
```

`gemini-3.1-pro-preview` natively reads mp4 and pulls register cues a still-frame
pass misses — handheld jitter character, cut rhythm, audio-driven pacing. Use
the video-analysis output as a second input to the blueprint, not a replacement.
</Step>

<Step title="Read and edit the scaffolded template">
The clone wrote a minimal `template.yaml` and copied the blueprint into
`composition.md`. Open both and fill the gaps.

```bash
ralphy template show clone-somecreator-style-001 -p
# → renders the scaffolded TEMPLATE.md (read-only preview)
```

The scaffolded `template.yaml` looks like this (auto-generated by `clone`):

```yaml
version: 1
kind: vibe-style
slug: clone-somecreator-style-001
source_slug: tiktok-somecreator-7293
source_url: "https://www.tiktok.com/@somecreator/video/7293..."
strict_look: true
prompt_only: false
created_at: "2026-05-20T..."
```

Edit it to match the full schema (`cli/lib/schemas/template.ts`) — add `id`,
`category`, `name`, `description`, `tags`, `requires`, `scenes`,
`estimated_cost_usd`, `estimated_duration_s`. The clone gives you a starting
point; the production-ready template needs the metadata to surface on the
suggest scorer.

```yaml
version: 1
id: clone-somecreator-style-001
kind: vibe-style
category: creator-lifestyle
name: "Somecreator deadpan POV"
description: >-
  Deadpan first-person POV monologs in the @somecreator register —
  shaky selfie 35mm, single-source kitchen light, deadpan delivery
  with extended pauses. Style lift from a 2026-Q2 source TikTok.
tags:
  - pov-first-person
  - deadpan
  - shaky-selfie
  - creator-lifestyle
requires:
  refs: 0
scenes:
  - id: scene-01
    role: hook
    duration_s: 3
    direction: "Deadpan cold-open, off-screen room sound."
  - id: scene-02
    role: body
    duration_s: 9
    direction: "Monolog escalates without raising volume — register stays flat."
  - id: scene-03
    role: cta
    duration_s: 3
    direction: "Drop the punchline, hold on the deadpan stare."
estimated_cost_usd: 2.40
estimated_duration_s: 15
references: []
```
</Step>

<Step title="Edit composition.md">
The blueprint synthesizer wrote a rough composition spec. Tighten it — clones
are starting points, not finished templates.

```bash
$EDITOR workspace/templates/clone-somecreator-style-001/composition.md
```

The composition.md should answer:

- What's the camera grammar? (35mm selfie, low angle, what's typical?)
- What's the lighting register? (single-source ambient, what direction?)
- What's the audio register? (deadpan VO + room tone? music bed off / on?)
- What's the cut rhythm? (one continuous take? micro-cuts on the punchline?)
- What does NOT belong? (the things the source uses incidentally that you don't
  want to copy literally — specific props, specific colors, specific dialogue).

The "what does NOT belong" section is load-bearing. It tells the agent what to
abstract from the source vs what to copy. Skipping it produces clone templates
that work only for videos near-identical to the source.
</Step>

<Step title="Register and lint">
```bash
ralphy template register workspace/templates/clone-somecreator-style-001/ --workspace
# → registers in the workspace registry (not the repo registry)
# → validates against the Zod schema, exits on E_TEMPLATE_*

bun run lint:templates
# → confirms the yaml parses, slug is kebab + not in deny list

ralphy template suggest "deadpan POV monolog shaky selfie kitchen"
# → expects clone-somecreator-style-001 at tier: primary
```

If the suggest scorer doesn't surface the clone on its canonical utterance,
edit `tags` and `description` in the yaml until it does. Workspace templates
that don't surface on suggest are reachable only by explicit slug — useful for
private one-offs but not for shareable templates.
</Step>

<Step title="Test-drive the clone on a fresh project">
```bash
ralphy template use clone-somecreator-style-001 \
  --project test-clone-001 \
  --name "Clone test" \
  --brief "15s deadpan POV about losing my favorite mug"
# → scaffolds a project using the clone template's vibe
```

Run the full pipeline (scenarist → art-director → editor) and render. Compare
the final mp4 to the source TikTok. If the register matches, the clone is
production-ready. If specific source-isms leak through (the same actor's
exact wardrobe, the same prop, the same setting), edit composition.md's "what
does NOT belong" section and re-run.
</Step>

<Step title="Promote to repo (optional)">
If the clone proves useful across multiple projects, promote it from
`workspace/templates/` to `templates/<category>/<slug>/` and open a PR using
the [new-template recipe](/cookbook/new-template). Workspace templates are
gitignored and user-local; repo templates ship to every clone of the
codebase.

```bash
mv workspace/templates/clone-somecreator-style-001 \
   templates/creator-lifestyle/clone-somecreator-style-001
ralphy template register templates/creator-lifestyle/clone-somecreator-style-001/
bun run lint:templates
```

The slug rules from the new-template recipe apply — drop the `clone-` prefix
and pick an archetypal name, since real-creator names are banned from repo
slugs (`DENIED_SLUG_TOKENS`). The `aliases:` field on the new yaml carries
the old `clone-*` slug for any existing workspace project referencing it.
</Step>

</Steps>

## Why this works

`ralphy clone` is the only correct entry point for "lift the style of an
existing video into Ralphy". The four chained back-stage verbs (`ref pull`,
`ref frames`, `ref analyze`, `ref blueprint`) work standalone for power users,
but the front-stage clone verb wires them in the right order, with the right
flags, into the right output shape. Running them by hand drops the
yt-dlp-into-workspace step or skips the audio describe pass; the clone verb's
existence is exactly to prevent that drift.

The default analyze path uses `gemini-2.5-flash` over sampled frames —
cheap (~$0.01 per clone for vision) and fast. For style work that depends on
*motion* — handheld jitter character, cut rhythm, audio-driven pacing — the
`ref analyze-video` path on `gemini-3.1-pro-preview` reads the full mp4 and
catches register cues the frame-sample pass misses. Use the video pass as a
*supplement* to the blueprint, not a replacement.

Clones land under `workspace/templates/`, not `templates/`. Workspace
templates are user-local, gitignored, and can carry creator names in their
slug (`clone-somecreator-style-001`) because they never ship. To promote to
the repo, the slug renames to an archetypal name and goes through the full
new-template PR review — `DENIED_SLUG_TOKENS` enforces this on repo slugs.
The workspace-then-promote two-step is the design that lets users iterate on
clones quickly without bloating the public template registry.

The `--strict-look` flag is the dial between "mirror this exactly" and "use as
inspiration". Strict-look mirrors palette, grading, and hook composition
verbatim in the blueprint. Without the flag, the blueprint describes register
abstractly. Use strict-look when the user says "copy the style"; drop it when
the user says "use this as one inspiration among many".

## Variations

- **Existing ref slug instead of URL.** `ralphy clone <slug>` skips the pull
  step and works against an already-pulled reference. Useful when you've
  already ref-pulled the URL for a research pass.
- **Skip the audio describe pass.** `--prompt-only` skips `audio-describe`,
  which is best-effort and adds ~$0.05 + 30s. The blueprint can still be built
  from visuals + transcript.
- **Custom blueprint vision model.** `--analyze-model google/gemini-2.5-pro`
  upgrades the frame analysis to the pro vision model (~3× cost, deeper read
  on complex compositions). Use when the source has busy / layered visuals.
- **Multi-source clone.** Run `clone` on three sources, then write a fourth
  blueprint that merges them. The merge is manual today — no verb chains
  multi-source synthesis automatically.
- **Skip the template scaffold.** Use `ref pull` + `ref analyze` + `ref blueprint`
  standalone if you want the analysis without the workspace template. Useful
  for ad-hoc research that doesn't need a reusable template.

## Pitfalls

<Warning>
The clone is a starting point, not a finished template. The auto-scaffolded
`template.yaml` is missing the metadata that makes the template surface on
`template suggest`. Edit the yaml to add `id`, `category`, `name`,
`description`, `tags` before the clone is useful beyond its source URL.
</Warning>

<Warning>
Workspace clones can carry creator names in their slug; repo templates
cannot. Promoting a clone with a creator-name slug fails the lint —
`DENIED_SLUG_TOKENS` blocks `oldspice`, `mrbeast`, `hormozi`, `huberman`,
`kardashian`, `rogan`, and the rest. Rename the slug to archetypal before
opening a PR.
</Warning>

<Warning>
Clones can drift into copying source-isms (specific actor wardrobe, specific
prop, specific dialogue) the user didn't intend. Edit composition.md's "what
does NOT belong" section explicitly — without it, the clone produces near-
identical derivatives of the source.
</Warning>
