title: "Author a new skill"
description: "ralphy skill new, namespace choice, frontmatter rules, the 1536-char description budget."
---

A skill is the smallest agent-routable artifact in Ralphy — one folder under
`.agents/skills/<name>/`, one `SKILL.md` inside it, YAML frontmatter on top and
a Markdown body underneath. This recipe walks the full authoring loop:
`ralphy skill new`, pick a namespace, write a description that fits the budget,
fill the body sections, lint, install, and verify the slash command fires.

## Brief

> "Every time we ship a brand-launch video, we want a fixed post-render checklist
> — confirm the wordmark renders on scene-06, confirm the persona master is
> reused on every scene, confirm cost stays under the brief's budget. Let's make
> a skill for it."

## Stack

- **Output:** `.agents/skills/brand-launch-checklist/SKILL.md`
- **Scaffolder:** `ralphy skill new <name>` (wizard from `cli/lib/skill/wizard.ts`)
- **Namespace:** `ralphy:` (user-invokable) or `ralphy-dev:` (maintainer-only)
- **Description budget:** ≤ 1536 chars (agentskills.io hard cap), ~1500 char soft ceiling
- **Lint:** `bun run lint:skills`
- **Install:** `ralphy skill install --agent claude`

## Walkthrough

<Steps>

<Step title="Run the scaffolder">
The scaffolder is interactive on TTY. It prompts for the intent line and at
least one trigger phrase, then writes a fresh `SKILL.md`.

```bash
ralphy skill new brand-launch-checklist
# ? Intent — one sentence describing what this skill does:
#   › Post-render checklist for brand-launch videos — wordmark fidelity, persona reuse, budget gate.
# ? Trigger phrases (comma-separated, e.g. 'do X, /run-X'):
#   › check the brand launch, /brand-launch-checklist, post-render audit
# → wrote .agents/skills/brand-launch-checklist/SKILL.md
```

For non-interactive / CI use, pass `--non-interactive --intent "<text>" --trigger "<phrase>"`
with one or more `--trigger` flags.
</Step>

<Step title="Choose the namespace">
Two namespaces ship:

- **`ralphy`** (default) — user-invokable. Visible in the slash-command menu
  after `ralphy skill install`. Examples: `postmortem`, `ralph-evaluator`,
  `ralph-researcher`.
- **`ralphy-dev`** — maintainer-only. Hidden by default; opt-in via
  `ralphy skill install --dev`. Examples: `release`,
  `remotion-best-practices`, `skill-creator`.

The brand-launch checklist is a user-facing post-render check → `ralphy:`.
Override with `--namespace ralphy-dev` at scaffold time if you're writing a
maintainer skill.
</Step>

<Step title="Write the description (within the 1536-char budget)">
The scaffolder writes a stub description from the intent line. Replace it with
a real description that respects the trigger budget.

Claude Code budgets roughly 1% of its context window for skill discovery
across every installed skill. Descriptions are concatenated for the menu and
"suggest this skill" surfaces; ~1500 chars is the soft ceiling per skill
(agentskills.io hard cap is 1536). Over-stuffing pushes sibling skills out of
the budget and the agent silently stops suggesting them.

```yaml
---
name: brand-launch-checklist
namespace: ralphy
description: >-
  Post-render audit for brand-launch videos. Checks wordmark fidelity on the
  final scene, verifies the persona master was passed as --ref on every scene
  gen, confirms total project cost stays inside the brief's budget. Emits
  checklist.json + checklist-report.md per project. Use after `ralphy render`
  when you want a structured sign-off before sharing the cut with the brand
  team.
when_to_use: post-render
allowed-tools:
  - Read
  - Bash
argument-hint: <project-id>
---
```

Three sentences max: what it does + what it produces, when the user reaches
for it, and (optionally) the closest adjacent skill it should not be confused
with. Skip synonym lists. Skip keyword stuffing — the trigger phrases for
routing fidelity belong in the body's `## Trigger` section, not in the
description.
</Step>

<Step title="Fill the body sections">
The body follows a conventional section order. The lint warns (not errors) on
missing sections, but every non-trivial skill should hit each:

```markdown
# Brand launch checklist

## Trigger

USE WHEN the user finished a render of a brand-launch project (a project
scaffolded from `multi-scene-product-launch` or any vibe-reference template
with `requires.refs >= 1`) and asks for an audit / sign-off / review.

EN: "audit this brand launch", "check the brand launch", "is this ready for
the brand team", "post-render check on `<project-id>`".

DO NOT FIRE for non-brand-launch projects, batch reviews (use `ralph-evaluator`),
or pre-render scenario gates (use `ralphy project score`).

## Hard invariants

- Never modify the project. Read-only audit.
- Always read `asset-manifest.json` + `generations.jsonl` first. Don't re-render.
- If the wordmark check fails on the final scene, surface the failing slot —
  don't auto-fix.
- Cost-vs-budget gate: warn at 80% of brief budget, refuse-to-pass at 100%.

## Workflow

1. Read `workspace/projects/<id>/asset-manifest.json` to enumerate scene anchors.
2. Read `workspace/projects/<id>/logs/generations.jsonl` to verify every scene
   gen carries the persona-master + product-master refs.
3. Run `ralphy project show <id> --status` to confirm render exists.
4. For each scene anchor, check the prompt for the locked-ref discipline.
5. Sum costs from `generations.jsonl`; compare to `workspace/projects/<id>/BRIEF.md`
   budget line.
6. Emit `checklist.json` (machine-readable pass/fail) and `checklist-report.md`
   (human-readable, with failing slot details).

## Outputs

- `workspace/projects/<id>/checklist.json` — pass/fail per check, machine-readable.
- `workspace/projects/<id>/checklist-report.md` — readable audit with failing
  slots and suggested fixes.

## Cookbook

(EN) "Audit the brand-launch on headphones-launch-001" → fires this skill.
(RU) "Проверь брендовый лонч headphones-launch-001" → fires this skill.

Common failure mode: persona-master ref dropped from one scene gen mid-batch.
Report surfaces the scene-id and the missing ref.
```

Move long ALSO FIRE / DO NOT FIRE / HARD INVARIANTS detail into the body —
not into the description. The body is what the agent reads after the skill
fires; the description is what the user reads before invoking it.
</Step>

<Step title="Lint">
```bash
bun run lint:skills
# → walks .agents/skills/*/SKILL.md
# → frontmatter parses, name is kebab-case + matches folder, description ≤ 1536 chars,
#   namespace is ralphy / ralphy-dev, body has ## sections (warning only)
```

A failing lint blocks merge in CI. Fix the offending field and re-run.
</Step>

<Step title="Install into Claude Code">
The installer drops the bundle into the user's chosen agent. v1.0 supports
Claude Code, Cursor, and Codex.

```bash
ralphy skill install --agent claude
# → drops .agents/skills/* into ~/.claude/skills/ (user scope by default)
# → for project scope: --scope project (drops into ./.claude/skills/)

# Maintainer-only skills:
ralphy skill install --agent claude --dev
# → also installs ralphy-dev:* skills
```

The first-run install (no `--agent` flag) launches a `@clack/prompts` wizard
that detects installed agents and asks for scope.
</Step>

<Step title="Verify the slash command fires">
```bash
# In Claude Code, type:
/ralphy:brand-launch-checklist
# → the skill should appear in the menu with the description
```

If the menu does not surface the skill, re-run `lint:skills` and re-install.
The most common failure mode is a frontmatter parse error that the installer
silently swallows.
</Step>

<Step title="Optionally add a routing row to AGENTS.md">
For skills that should fire on natural-language utterances (not just slash
commands), add a row to `AGENTS.md` so the routing table covers it:

```bash
ralphy skill new brand-launch-checklist \
  --add-to-routing \
  --row "Brand-launch post-render audit — wordmark, ref discipline, budget gate"
# → also inserts a row into AGENTS.md routing table
```

The agent reads `AGENTS.md` on every user request and matches the intent to a
routing row. A skill that fires on natural language needs both the SKILL.md
and the routing row.
</Step>

</Steps>

## Why this works

The frontmatter / body split is the trigger-budget discipline. Claude Code
budgets roughly 1% of its context window for skill discovery across every
installed skill — descriptions are concatenated for the menu and the "suggest
this skill" surfaces. ~1500 chars per skill is the soft ceiling (1536 is the
hard agentskills.io cap). Two skills with bloated descriptions push sibling
skills out of the budget and the agent silently stops suggesting them. The
short description in frontmatter buys cheap discoverability for every skill;
the long ALSO FIRE / DO NOT FIRE / HARD INVARIANTS detail goes in the body
where it costs nothing until the skill actually fires.

The two-namespace split (`ralphy:` vs `ralphy-dev:`) maps cleanly onto user vs
maintainer intent. End users typing `/<TAB>` in Claude Code see
`/ralphy:postmortem`, `/ralphy:ralph-evaluator` — they don't see
`/ralphy-dev:release` (which ships the binary, not the user's project).
Maintainers opt into the dev set with `ralphy skill install --dev`. Both
namespaces ship through the same lint and installer plumbing.

The lint enforces what the runtime can't recover from gracefully —
kebab-case name, frontmatter parse, description ≤ 1536 chars, namespace
membership. Body sections are warnings, not errors, because some skills are
intentionally minimal (a `/lint-this` shim that delegates entirely to a CLI
command, for example).

The `ralphy skill new` wizard is the canonical authoring path. Hand-writing
SKILL.md by hand works but invites frontmatter-parse failures that the
installer silently swallows; the wizard's scaffold is lint-clean by
construction.

## Variations

- **Maintainer skill.** Pass `--namespace ralphy-dev` to scaffold under the
  maintainer set. Hidden from the default install.
- **Slash-only skill.** Skip the natural-language routing row. The skill fires
  only when the user types `/ralphy:<name>`. Use for niche / advanced flows
  that shouldn't compete for routing budget.
- **Documentation-only skill.** Set `disable-model-invocation: true` in the
  frontmatter. The skill becomes a documentation lookup — it never spawns a
  model call. Use for protocol / convention reference skills.
- **Pre-flight skill.** Set `when_to_use: pre-flight` and design the trigger
  around briefs that haven't been scaffolded yet. Skills can fire at any
  pipeline stage.
- **Tool allowlist.** Set `allowed-tools: [Read, Bash]` to constrain what the
  skill can call. Reduces blast radius on read-only audit skills.

## Pitfalls

<Warning>
Description over 1536 chars fails the lint and refuses to install. Move
trigger lists / ALSO FIRE / DO NOT FIRE detail into the body — the description
is for menu rendering, not for routing fidelity.
</Warning>

<Warning>
Folder name must match `name:` field exactly. The lint enforces this. A
mismatch makes the skill silently unreachable through the installer because
the installer maps by folder and the menu reads `name:` from frontmatter.
</Warning>

<Warning>
A skill that should fire on natural-language utterances also needs a row in
`AGENTS.md`. The `--add-to-routing` flag handles this at scaffold time.
SKILL.md alone is reachable only via the slash command.
</Warning>
