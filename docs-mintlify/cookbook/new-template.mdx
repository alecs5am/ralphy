---
title: "Author a new template"
description: "Folder layout, template.yaml schema, vibe-reference vs vibe-style, register, PR back."
---

A template is the smallest reusable Ralphy artifact above a single project — a
named pattern that `ralphy template suggest "<utterance>"` can route to and
`ralphy template use <slug>` can scaffold from. This recipe walks the full
authoring loop: pick a category, pick a kind, lay out the folder, write the
manifest, write the body docs, register the template, run the lints, and open
a PR.

## Brief

> "We just shipped three videos in the same caught-on-bodycam-bodyguard register —
> shaky over-the-shoulder, military comms in the audio, 1:1 square. Let's turn
> that into a template so the next batch is one CLI call."

## Stack

- **Output:** `templates/<category>/<slug>/` with `template.yaml`, `template.json`, `TEMPLATE.md`, plus the format-specific files
- **Schema:** `cli/lib/schemas/template.ts` (`version: 1`, kebab slug, archetypal-only)
- **Kinds:** `vibe-reference` (full-stack with composition + reference example) or `vibe-style` (prompt cookbook with hooks + camera vocab + worked examples)
- **Categories:** `b2b-saas`, `dtc-commerce`, `creator-lifestyle`, `entertainment-viral`, `cinematic-narrative`
- **Lint:** `bun run lint:templates`, `bun run lint:motion-graphics`
- **Register:** `ralphy template register <path>`

## Walkthrough

<Steps>

<Step title="Pick a category by audience, not by visual style">
Five categories, ranked by *who's watching* and *why they'd convert / share*.
The category drives discovery and tagging; the visual style is captured in the
template body, not the category.

```bash
ralphy template list -p
# → review what's already there to avoid duplication
```

The bodycam-bodyguard register has scroll-stop entertainment intent, not B2B
or DTC commerce intent. → `entertainment-viral/`.
</Step>

<Step title="Pick a kind">
Two kinds ship today:

- **`vibe-reference`** — full-stack production template. Ships a worked reference
  example, a composition spec, a model stack rationale, and prompt fragments.
  Five of these in the repo (`before-after-product`, `talking-head-rant`,
  `podcast-clip`, etc). Use when you have one canonical shipped project the
  template should clone-and-adapt from.
- **`vibe-style`** — prompt cookbook. Ships hooks copy, camera vocabulary,
  prompt cookbook with worked-example prompts. 38 of these in the repo. Use
  when you have a *style* (camera + lighting + register vocabulary) without a
  single canonical project to clone.

The bodycam recipe is style-driven across three shipped projects — `vibe-style`.
</Step>

<Step title="Lay out the folder">
```text
templates/entertainment-viral/bodycam-bodyguard/
├── template.yaml             # the manifest (Zod-validated, version: 1)
├── template.json             # legacy JSON manifest (mirrors yaml during transition)
├── TEMPLATE.md               # LLM-consumable doc — the agent reads this on `template use`
├── hooks.md                  # vibe-style only: hook copy by length / register
├── prompt-cookbook.md        # vibe-style only: per-mode worked-example prompts
└── reference/                # optional: shipped frames / final cuts for the agent to read
    ├── frames/
    └── source-project.md
```

For `vibe-reference`, replace `hooks.md` + `prompt-cookbook.md` with
`composition.md`, `model-stack.md`, `reference-example.md`, `fragments.md`.

```bash
mkdir -p templates/entertainment-viral/bodycam-bodyguard/reference/frames
```
</Step>

<Step title="Write template.yaml">
The Zod schema in `cli/lib/schemas/template.ts` enforces every field. Slugs
must be kebab-case and must not contain any banned creator / brand token (`oldspice`, `mrbeast`, `hormozi`, etc — full list in `DENIED_SLUG_TOKENS`).

```yaml
version: 1
id: bodycam-bodyguard
aliases: []
kind: vibe-style
category: entertainment-viral
name: "Bodycam bodyguard"
description: >-
  Shaky over-the-shoulder bodycam realism — military comms in the audio,
  1:1 square, caught-on-duty register. Derived from three shipped projects
  in 2026-Q2.
tags:
  - bodycam
  - over-the-shoulder
  - square
  - entertainment-viral
  - shaky-handheld
requires:
  refs: 0
  music_style: "off — diegetic comms only"
  voice_style: "military-comms-radio-distorted"
scenes:
  - id: scene-01
    role: hook
    duration_s: 4
    direction: "Hard cold-open. Bodycam tilt + radio crackle hook."
  - id: scene-02
    role: body
    duration_s: 8
    direction: "Action beat — encounter with the threat, comms escalate."
  - id: scene-03
    role: cta
    duration_s: 3
    direction: "Resolution + diegetic out-bark."
estimated_cost_usd: 3.20
estimated_duration_s: 15
references: []
```

The `requires` block is the scaffolding contract — what the scenarist / art
director expects from the user before generating. `refs: 0` means no
user-supplied reference is required by default; the gate fires only if the
user's brief names a real brand or person on top of the template.
</Step>

<Step title="Write TEMPLATE.md (the LLM-consumable doc)">
This is the file the agent reads on `template use`. The shape is documented in
`docs/playbooks/producer/template-extract.md`. The key sections:

```markdown
# Bodycam bodyguard

> Shaky over-the-shoulder bodycam realism — 1:1 square, military comms, caught-on-duty register.

## When to reach for this

- The brief mentions "bodycam", "over the shoulder", "tactical", "comms".
- The user wants scroll-stop entertainment-viral, not commerce or B2B.
- 1:1 square aspect (16:9 reads as polished broadcast; portrait reads as AI).

## Vibe constants

- **Aspect:** 1:1 only. The square aspect IS the caught-on-bodycam trick.
- **Lighting:** ambient single-source, never studio. Day-shoot OR pitch-night with bodycam IR.
- **Camera:** chest-mounted point-of-view, low-angle, shaky handheld micro-jitter throughout.
- **Audio:** diegetic only. Radio crackle, military comms, footsteps. NO music bed.

## Axes (what to vary across a batch)

- Threat type — civilian dispute / nighttime patrol / building entry.
- Comms voice register — calm-veteran / hyped-rookie / cold-handler.
- Setting — corporate corridor / parking structure / suburban front porch.

## Models

- Image anchors: `google/gemini-3-pro-image-preview` (default since 2026-05-20) for the 1:1 caught-on-bodycam fidelity and operator-identity consistency across cuts.
- Video: `kwaivgi/kling-v3.0-pro --audio` for the diegetic comms.

## Worked example

See `reference/source-project.md` for the canonical shipped project.
```

For `vibe-style`, also write `hooks.md` (length × register matrix of hook copy)
and `prompt-cookbook.md` (per-mode worked-example prompts).
</Step>

<Step title="Register and lint">
```bash
ralphy template register templates/entertainment-viral/bodycam-bodyguard/
# → validates the yaml against the Zod schema, registers in the workspace registry
# → exits 1 with E_TEMPLATE_SLUG_INVALID / E_TEMPLATE_VERSION_UNSUPPORTED on failure

bun run lint:templates
# → confirms every template.yaml parses, slug is kebab + not in deny list,
#   required body files exist for the declared kind

bun run lint:motion-graphics
# → only fires if the template declares a motion-graphics composition layer
```
</Step>

<Step title="Verify routing">
The template suggest scorer reads `tags` + `name` + `description`. Confirm the
template surfaces on its canonical utterance.

```bash
ralphy template suggest "shaky bodycam over-the-shoulder military comms 1:1"
# → expects bodycam-bodyguard at tier: primary, score ≥ 0.5
```

If the score is below `0.5`, edit `tags` / `description` in the yaml until the
canonical utterance hits primary. Templates that don't surface on their
canonical utterance are dead code.
</Step>

<Step title="Update the manifests and open the PR">
Two repo-level manifests reference the template:

- `templates/CATEGORIES.md` — the full slug-by-category roster
- `templates/TOP.md` — the Top-20 viral playlist (add only if the template
  belongs in the curated viral set)

Edit the relevant tables, commit, and open a PR. The PR description should
include: source projects the template was derived from, agent test-drive
checklist (`ralphy template use bodycam-bodyguard --project test-001 …` →
render → eval), and a link to the final mp4 of one shipped derivative.

CI runs `lint:templates`, `lint:motion-graphics`, and the suggest-score check
on every PR. A failing lint blocks merge.
</Step>

</Steps>

## Why this works

The two-kind split (`vibe-reference` vs `vibe-style`) maps onto the two
intuitions an agent has when scaffolding: "I want to clone this exact shape" or
"I want this style in a new shape". `vibe-reference` templates ship a worked
composition spec the agent imitates structurally; `vibe-style` templates ship a
vocabulary the agent applies to a scenario it writes from scratch. Mixing them
into one kind would force every template to ship both layers, doubling the
authoring cost.

The five-category audience split (`b2b-saas`, `dtc-commerce`, `creator-lifestyle`,
`entertainment-viral`, `cinematic-narrative`) is by *who's watching*, not by
visual style. Visual styles cluster within each audience — a B2B yap-talking-head
and a creator-lifestyle storytime can share camera grammar but live in
different categories because the watcher and the conversion intent differ. The
category drives discovery and the suggest scorer; the visual style lives in the
template body.

The Zod schema in `cli/lib/schemas/template.ts` is the source of truth. The
loader rejects unknown fields, unsupported `version` values, and banned slug
tokens (a maintainer-curated list of real creator / brand names that must
never appear in slugs — creator references stay legal as prose inside
`README.md` / `composition.md`, never in the slug). The lint runs on every
PR; a failing lint blocks merge.

The suggest-score check is the routing test. Templates that don't surface on
their canonical utterance with `score ≥ 0.5` are unreachable through the
producer's normal entry point and effectively dead code. The lint enforces
this so templates ship with at least one canonical utterance that scores
primary.

## Variations

- **vibe-reference instead of vibe-style.** Drop `hooks.md` + `prompt-cookbook.md`;
  add `composition.md`, `model-stack.md`, `reference-example.md`, `fragments.md`.
  Use when the template clones one canonical project.
- **Workspace-only template.** Write under `workspace/templates/<slug>/` instead
  of `templates/<category>/<slug>/`. Gitignored, never PR'd, user-local. Register
  via `ralphy template register --workspace`.
- **Aliases for slug renames.** The `aliases:` field carries old slugs the
  template used to ship as; the loader matches both old and new for at least one
  major-release cycle. Use when renaming a slug post-launch.
- **Required refs.** Set `requires.refs: 1` (or `2`) when the template only works
  with a user-supplied reference (logo, product photo). The gate fires before the
  scaffold completes.
- **Custom estimated duration / cost.** `estimated_cost_usd` + `estimated_duration_s`
  power the producer's `--dry-run` cost preview. Fill them honestly — under-estimating
  defeats the budget gate.

## Pitfalls

<Warning>
Slug must not contain any token in `DENIED_SLUG_TOKENS`. Real creator and brand
names (`oldspice`, `mrbeast`, `hormozi`, `huberman`, `kardashian`, `rogan`,
etc) are banned from slugs. Creator references stay legal as prose inside
`TEMPLATE.md`, never in the slug. The schema enforces this — the lint surfaces
the offending token in the error.
</Warning>

<Warning>
A template that doesn't surface on its canonical utterance via `template
suggest` with `score ≥ 0.5` is unreachable. Always test the suggest path
before opening the PR. Edit `tags` and `description` until the score lands
primary.
</Warning>

<Warning>
Do not overwrite an existing slug. `template register` exits with
`E_ALREADY_EXISTS` when the slug collides. Use `aliases:` on the new template
or pick a different slug. The aliases path lets the loader serve old and new
during deprecation.
</Warning>
