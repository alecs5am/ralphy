# Before real users: desktop release audit

Audit and implementation date: 2026-09-16. Source baseline: `6ce0af58` (`main`). Work branch: `fix/desktop-release-readiness`.

The descriptions below record the original audit findings. The implementation ledger at the end supersedes their original observed state. Checked items mean the defect was fixed or the unsupported promise was removed; they do not waive the separate release verification gates.

**Verdict after implementation: local defects are fixed; six external release gates remain.** There are 42 findings: 36 implemented and six release-verification gates (REL-26–29, REL-31–32). The second pass fixed historical result reuse, complete text inputs, generated-output counting, video history, browser recovery, Save to Unit and chat organization. Follow-up checks also fixed hidden credential fallback and cross-profile chat migration. The implementation ledger records the evidence and the limits of local verification. The requested provider connections and recovery of existing demo chats were applied to the local production profile; no media was generated or published.

This is an evidence-based backlog, not a claim that every possible defect has been found. `Confirmed` means reproduced in the native app or established by tracing the implementation. `Release verification` means the scenario still needs execution; it is not a proven bug. Checkboxes remain open until the acceptance criteria pass, or the unsupported feature is removed from the release surface.

## P0 — data integrity and user control

- [x] **REL-01 — Enforce the permission policy shown in Settings.** **Confirmed.** Settings promise review of shell commands, paid runs and publishing, and network isolation when the network switch is off. These preferences are stored but are not consumed by the agent execution boundary. Codex requests use `approvalPolicy: "never"`; its mode only changes the sandbox. New conversations default to `full`, despite Settings showing “Ask for writes and shell.”
  - Evidence: `apps/desktop/src/pages/settings/ui/pages-permissions.tsx:47`, `apps/desktop/src/shared/model/app-preferences.ts:27`, `apps/desktop/src/features/agent-chat/model/chat-state.ts:124`, `apps/desktop/electron/agent/codex-session.ts:254`, `apps/desktop/electron/agent/codex-session.ts:525`.
  - Required: one effective policy enforced at execution time, accurate mode labels, explicit opt-in to unrestricted access, and actual approval handling wherever the UI promises approval. Remove unimplemented policy switches if they cannot be enforced in this release.
  - Acceptance: new chats and resumed sessions obey the same policy; exercise file writes, shell, outbound network, paid calls and publishing through each supported harness. “Plan only” must not mutate; “Ask” must actually ask before the promised operations.

- [x] **REL-02 — Stop silently discarding old conversations and message text.** **Confirmed, reproduced with the real reducer.** Creating 31 chats retains 30 and removes the first. Saving and loading also slice to the last 30. Oversized entry text is truncated. The UI has no user-approved retention/archive flow for this loss.
  - Evidence: `apps/desktop/src/features/agent-chat/model/chat-state.ts:19`, `:266`; `apps/desktop/src/features/agent-chat/model/chat-storage.ts:49`, `:181`, `:213`.
  - Required: durable, paged history; explicit archive/delete controls; migration from current local storage; preserve full messages or explicitly mark recoverable truncation. Keep quota/write failures visible and recoverable.
  - Acceptance: 31+ conversations and a large transcript survive restart with their first messages, ordering, attachments and model/session metadata intact. Storage exhaustion must not silently replace valid history.

- [x] **REL-03 — Replace the incomplete portable import/export contract before presenting it as backup or transfer.** **Confirmed by source.** The export manifest sets artifacts, objects, units, compositions, builds, evaluations, presentations, campaigns and calendar to empty arrays. Documents contain headers but no revision bodies. Import creates workspace/project/social-account shells and maps other entity IDs to themselves without recreating their records. It can report success without transferring the content.
  - Evidence: `cli/lib/store/portable.ts:120` (import), `:207` (manifest construction). Chat history, canvas drafts and video drafts also live outside this manifest: `apps/desktop/src/features/agent-chat/model/chat-storage.ts`, `apps/desktop/electron/canvas/store.ts`, `apps/desktop/electron/video-workspace/store.ts`.
  - Required: complete self-contained archive and restore, including revision bodies, R0 provenance, media bytes, presentations/captions, chats, attachments and editable drafts; validate and remap every reference. Exclude credentials, invalidate machine-specific sessions and request account relinking. Until then, clearly mark/disable the partial contract as unsuitable for backup.
  - Acceptance: export a populated workspace, restore into an empty library on another home/device with the source unavailable, and compare entity/revision counts and media hashes. Open all transferred chats and media offline. Failed import must leave no falsely successful partial workspace. The existing manually prepared demo ZIP is not proof that this product contract works.

## P1 — first use and core workflows

- [x] **REL-04 — Provide a usable empty-library onboarding flow.** **Confirmed in an isolated fresh HOME.** After the runtime could start, the app displayed zero workspaces/projects and an empty recent-workspaces list, without create/import actions. There is no route to normal chat use from this screen.
  - Evidence: `apps/desktop/src/pages/library/ui/LibraryScreen.tsx`; native first-run capture. Project listing also lacks a create-project action: `apps/desktop/src/pages/workspace-projects/ui/WorkspaceProjectsScreen.tsx`.
  - Required: create workspace, create first project, import existing data, and accessible provider/runtime setup. Explain where data is stored.
  - Acceptance: a person with a clean account can reach a working project and first chat entirely through the app, without CLI seeding or a prebuilt demo archive.

- [x] **REL-05 — Make startup/runtime failures actionable.** **Confirmed.** A fresh development environment without Bun produced “The operation could not be completed” / “Home library unavailable.” Supplying the prerequisite allowed startup. The generic error does not distinguish a missing executable from permissions, corruption or a locked database.
  - Evidence: native isolated startup; `apps/desktop/src/pages/library/ui/LibraryScreen.tsx`, `apps/desktop/electron/ralphy/session.ts` and IPC error handling.
  - Required: prerequisite checks, a redacted diagnostic reason, specific recovery actions and a retry that preserves the existing library. Distinguish source-checkout requirements from bundled-runtime requirements.
  - Acceptance: missing runtime, unreadable library, failed migration and unavailable home directory show distinct recoverable states. Test packaged startup separately; the development failure is not evidence that the packaged runtime is missing.

- [x] **REL-06 — Fetch all workspace Units and refresh them after changes.** **Confirmed.** The workspace screen fans out to projects, takes only the first units/publications page, and never follows its cursor. The reader's page limit is 50. Its effect key contains root epoch and project IDs, not unit activity. Workspace-owned units (`project_id IS NULL`) are omitted entirely.
  - Evidence: `apps/desktop/src/pages/workspace-units/ui/WorkspaceUnitsScreen.tsx:69`, `:92`; `apps/desktop/electron/ralphy/project-reader.ts:58`, `:1164`.
  - Required: paged aggregation with an explicit scope, activity-driven invalidation, retry/partial-state handling and bounded concurrency across projects. Either support workspace-owned units or make their exclusion explicit everywhere, including counts.
  - Acceptance: >50 units in one project, multiple projects, a workspace-owned unit, a failed project read and a unit created while this view is open all produce complete, consistent results.

- [x] **REL-07 — Validate provider credentials, not just their shape/presence.** **Confirmed.** Generation provider status means a stored/environment key exists. Saving validates syntax but does not authenticate; the current copy acknowledges this. This does not meet the expected valid/invalid key workflow.
  - Evidence: `apps/desktop/electron/canvas/generation-credentials.ts:17`, `:38`, `:51`; `apps/desktop/src/pages/settings/ui/pages-providers.tsx:68`.
  - Required: non-billing connection check; distinguish saved, checking, valid, rejected, limited and temporarily unreachable. Explain credential scope/source across chat providers, generation providers and project connectors. Never display or log the key in diagnostic output.
  - Acceptance: valid, revoked, malformed and rate-limited credentials; offline/retry; save/restart/remove; stored-versus-environment precedence; the generation/chat flow uses the credential the UI says it uses.

- [x] **REL-08 — Keep existing MDX Unit cards current after agent changes.** **Confirmed by source.** A card loads its summary when its reference or retry counter changes, but does not subscribe to project activity. A later turn can add revisions while an existing card keeps its earlier count/previews.
  - Evidence: `apps/desktop/src/features/agent-chat/ui/AgentMessage.tsx:23–41`.
  - Required: invalidate or refresh the summary when its unit changes; preserve expanded-page state where possible and protect against stale async responses.
  - Acceptance: request 4 variants, then extend the same unit to 8 and 16. The earlier card and open viewer update without remounting the chat. Include >50 revisions, deleted/missing references and cross-workspace references.

- [x] **REL-09 — Make Marketplace install/disable affect the agent, or describe it as a bookmark.** **Confirmed by source.** Bundled installs are local records. The enabled flag is used for Marketplace display, with no agent-context consumer found. The detail view nevertheless states that disabling an item stops its agent from reaching for it.
  - Evidence: `apps/desktop/electron/marketplace-installs.ts`, `apps/desktop/src/pages/marketplace/ui/MarketplacePackItemDetail.tsx:62–71`; call sites of `loadMarketplaceInstalls` and the install store.
  - Required: enforce workspace-specific enabled state in context/skill resolution, or remove the activation claim and rename the action. Handle failed persistence without suggesting the choice will survive restart.
  - Acceptance: enable/disable/uninstall changes the actual next-turn context in the chosen workspace and does not affect a different workspace. Verify after restart.

- [x] **REL-10 — Fix the native public Marketplace catalog failure.** **Observed in the native app; root cause not yet isolated.** Multiple categories show public-library unavailable. Calling its preload API also returns the generic operation-failed error. The catalog endpoint returned HTTP 200 and the source projector parsed that same response into 42 items outside Electron, so “the server is down” is not established.
  - Evidence: `apps/desktop/electron/marketplace-library.ts:388–429`, `apps/desktop/electron/preload.ts:99`; native Marketplace captures.
  - Required: trace the Electron IPC/fetch/cache boundary, retain a safe diagnostic cause and offer retry/cached results without duplicate banners.
  - Acceptance: cold/warm cache, offline, corrupt cache, timeout and successful online refresh work in the packaged app, not only in an isolated parser test.

## Implementation ledger

### Completed product changes

- **REL-01:** New chats default to Read-only files. Settings and composer share supported modes. Removed unenforced approval/network switches; explain that connected MCP tools retain their provider permissions. Existing conversations keep their selected mode. Ralphy does not promise its own external-action approval queue.
- **REL-02:** Atomic main-process chat storage replaces browser quota storage; no 30-chat retention limit or silent text slicing. Migration keeps the original until disk accepts it. Conflict, corruption and failed-save states retain recoverable data. Imports receive fresh chat IDs; events are fenced by library and workspace.
- **REL-03:** Portable v2 restores the domain graph, media bytes, documents/revisions, provenance, presentations, memory, chats, Canvas and video drafts. Hash/path/schema validation and SQL/file rollback prevent partial success. Added native export/import dialogs and empty-library CLI import. Credentials and live provider sessions are excluded; imported chats start with Read-only files and accounts require reconnection. Editable composition checkouts are included; older archives can recover sealed sources from immutable objects. Both current and older archives rendered after the source library was made unavailable. Current archive limit: 1 GiB. User-authored file bytes remain exact and must be reviewed for embedded secrets before sharing.
- **REL-04–05:** Create/import a workspace and create a project from the UI. Fresh SQLite library and bucket watcher initialization work. Startup errors distinguish missing runtime, inaccessible/full storage, locked/corrupt data and migration failures, with retry and safe diagnostic copy.
- **REL-06, REL-08:** Follow all Unit/publication cursors, include workspace-owned Units, preserve partial results and retry failures. Workspace overview requests respect the runtime limit of 50 per page; a real bridge regression covers 105 Units and 105 shared assets. Shared counts are read from paged workspace-owned assets instead of a constant zero. Unit lists and existing MDX cards refresh on activity; stale workspace responses cannot replace the active view. MDX supports 4/8/16/55 variants and scoped references.
- **REL-07:** OpenRouter keys have a non-billing authentication check and distinct saved/valid/rejected/unreachable states. Desktop Create, Canvas and integrated agents now use the same app-selected generation credentials; see REL-41. Standalone CLI scoped credential resolution is unchanged. Canvas text and media use runtime connectors. Canvas text no longer requires an unrelated Codex login. OpenRouter authentication probes work with zero or multiple workspaces and distinguish rejected credentials from connection errors; a synthetic invalid key was checked against the real non-billing endpoint. Each accepted text attempt records actual cost or unknown, supports cancellation and does not retry a paid request automatically. Other generation services honestly show saved/untested until used.
- **REL-09–10, REL-17:** Marketplace items are honestly saved references rather than pretend agent installs. Saves persist atomically and failures remain visible. Native public catalog loading was repaired and returned 42 items. Removed unsupported downloads/update/contribution destinations and ModelScope from normal navigation.
- **REL-11–16:** Removed simulated updater, cleanup and inert settings. Updates link to manual releases. Cache cleanup deletes only browser cache and reports measured bytes. System/storage diagnostics measure writable library, capacity, runtime and actual environment. Retained theme, reduced motion, profile, chat send shortcut, default agent and default access are wired to behavior. Library relocation is no longer promised.
- **REL-18:** Media review uses durable revisions/evaluations/feedback. Approved and Needs work survive restart, use current revision guards and preserve the last good state on conflict. Feedback length matches the runtime's UTF-8 limit.
- **REL-19–20:** R0 has a distinct Original badge; only the viewed revision receives active styling. The current card scrolls into view without changing ascending order. Chat Unit views open their video editor inside the workbench. Calendar also opens project-owned and workspace-owned Units in the right panel.
- **REL-21–22:** Calendar ranges and empty states are consistent. Removed decorative hashtags; disconnected scheduling links to account setup. First connection/reconnect verifies Postiz before saving and imports supported accounts. Failed remote scheduling leaves one local draft rather than offering duplicate creation. Caption, pinned revision and per-publication platform settings are preserved. Ambiguous remote outcomes block resubmission, movement and removal until confirmed. Calendar exposes Check status through the existing reconciliation engine; this reads remote metadata and never resubmits or cancels. Unconfirmed status remains visible and safely blocked.
- **REL-23:** Replaced implementation jargon on customer surfaces. Shared Library exposes working browsing, previews, revision selection and reveal; unfinished import/promotion/rights/usage controls are hidden. Overview shows measured totals or unknown, without placeholder analytics destinations. Shared Library uses asset/revision language and actual keyboard hints rather than internal IDs. Provider failures display safe actionable text; cancelled/new failed chat runs have accurate labels.
- **REL-30 implementation:** Documents can be created, edited and saved with conflict recovery. Read/edit layouts fit 400–440 px panels with long titles and unbroken text. Saving a title updates list/search identity as well as the revision. Memory edits and archival survive bridge restart. Canvas saves reject stale revisions. Video split/duplicate keeps media IDs, missing sources preserve edits, and rendering produces a durable new Unit revision while retaining presentation captions/references.
