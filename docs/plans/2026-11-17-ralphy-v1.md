# Ralphy v1: build contract

Status: approved by the owner 2026-11-17. Python core, plain files instead of SQLite, at most 10 skills. Executed in waves directly on `main`. This file is the shared contract for every agent in the rebuild; if your brief and this file disagree, this file wins, and you report the conflict.

Amended by the owner 2026-11-17 (release 0.6.0, wave 4): one working render per video (`render.mp4`) and versions as code only; the panel plays versions live and compares two side by side; `ralphy panel` starts in the background from any chat; every skill but the entry skill is named `ralphy-<job>`. The sections below are the amended contract.

## Product

A plugin for the user's coding agent. It ships: trendwatching (a hosted trend base plus custom niches), `ralphy panel` (Content and Accounts), posting to the user's own accounts through the agent, and a hosted component library. Two entities: Content and Account. Loop: copy a working reference (reverse), rework it for the account (remake), post, read stats, iterate.

Principle: Ralphy holds only what an agent cannot hold on its own: state across sessions, the browser sessions of the user's accounts, the hosted trend base and library, and the panel. Media work is done by the agent with ffmpeg, HyperFrames and the bundled `tools/`.

## Runtime

- Python 3.11 or newer, a uv project at the repository root: `pyproject.toml` and `uv.lock` committed, package directory `ralphy/`, run as `python -m ralphy`.
- Core dependencies stay small: `pyyaml`, `patchright` (posting). Dev dependencies: `pytest`, `ruff`. Heavy media or ML libraries never go into the core; each tool declares its own dependencies inline (PEP 723) and runs through `uv run`.
- Bun or Node is used only by HyperFrames: `render` runs `bunx hyperframes@0.6.31 render <dir> --output <mp4>` (fallback `npx -y hyperframes@0.6.31`), and installs Bun on demand when neither exists.
- `bin/ralphy` (switched in wave 3) resolves its root through symlinks, installs uv when missing (`curl -LsSf https://astral.sh/uv/install.sh | sh`), then runs `exec uv run --quiet --project "$ROOT" python -m ralphy "$@"`.
- CLI: `argparse`. Each verb is a module `ralphy/commands/<verb>.py` exposing `register(subparsers)`; `ralphy/cli.py` discovers them, so agents add verbs without editing a shared file.
- Output: every command takes `--json` and then prints exactly one JSON object on stdout. Errors: `{"ok": false, "error": {"code": "E_...", "message": "...", "hint": "..."}}` and exit code 1. Without `--json`, short human text.
- Checks: `uv run ruff check ralphy tools tests` and `uv run pytest`. Tests use a temporary `RALPHY_HOME`, `RALPHY_CONFIG_DIR` and `RALPHY_CACHE_DIR`; they never touch real user folders, the network, paid APIs or a real browser login.

## Folders

All names are lowercase kebab-case.

`RALPHY_HOME` (default `~/ralphy`) holds everything a person browses:

```
~/ralphy/
  <account>/                      an Account, e.g. ui-effects
    account.md                    YAML frontmatter + markdown body (persona, style lock, rules)
    posts.csv                     one row per post
    stats.csv                     stat snapshots fetched from platforms
    videos/<nnn>-<slug>/
      index.html ...              the working tree: the HyperFrames composition and its files; new content references media as media/<file>, migrated content keeps its own relative paths (compositions/, assets/, params.js, vendor/, ...)
      render.mp4                  the one working render of the working tree; `ralphy render` overwrites it
      versions/v1/ v2/ ...        code snapshots made by `content save`: the working tree without media/, versions/, notes.md, render.mp4 and without any *.mp4 at any depth; files are APFS clones (cp -c, else a copy; never hardlinks, which would follow later edits)
      media/                      generated and source media, append-only
      notes.md                    YAML frontmatter + body
    refs/<ref-slug>/              a raw reference: source.mp4, source.json, frames/, transcript.json, breakdown.md
  inbox/                          the same shape without account.md: Content not assigned to an Account
```

`RALPHY_CONFIG_DIR` (default `~/.config/ralphy`): `keys.env` (mode 0600, `NAME=value` lines), `profiles/<account>-<platform>/` (browser profiles, mode 0700).

`RALPHY_CACHE_DIR` (default `~/.cache/ralphy`): `render/` (temporary render directories), `post/<post-id>.mp4` (the upload copy of `render.mp4`, made by `post run`), `panel/` (`server.json` with the running panel's pid, port and URL; `server.log`; posters and probes), trend and library caches. Safe to delete at any time.

There is no `renders/` folder and no top-level `<account>/<nnn>-<slug>.mp4` clone (both existed before 0.6.0).

Legacy data (`~/.ralphy`, `<checkout>/.ralphy`) is never read or written by the new code. Only the one-time migration reads it, read-only.

The body is free markdown: persona, a `## Style` section (the style lock), rules.

### notes.md frontmatter

```yaml
title: Type Charge
account: ui-effects         # null in inbox
refs: [refs/type-charge-original]   # paths under the account folder, or URLs
```

Keys: `title`, `account`, `refs`, `caption`, `created_at`. Readers ignore unknown keys (older notes may still carry `selected`). The body is free markdown: brief, what was copied from which reference, decisions.

### Render state

`content list` and `content show` report `render` (the absolute path of `render.mp4`, or null), `render_stale` (true when a working-tree file or subfolder other than `notes.md`, outside `media/` and `versions/`, hidden names aside, is newer than `render.mp4`), `rendered_at` (its mtime, UTC) and `versions`. `ralphy render` stamps `render.mp4` with the moment it read the tree, so a file edited during a render marks the render stale.

### posts.csv

Columns: `id,content,platform,handle,status,scheduled_at,posted_at,url,render,caption,error`.

- `id`: `p_` plus 8 hex characters. `content`: `<account>/<nnn>-<slug>` relative to `RALPHY_HOME`. `render`: the path of the Content's `render.mp4` relative to `RALPHY_HOME`.
- `status`: `planned` → `approved` → `uploading` → `published` | `unknown` | `failed` | `needs_login`; or `cancelled`. `unknown` is written before the irreversible click and is never retried without a check.
- Dedupe: a row with the same `content`, `platform` and `handle` and a status in `approved`, `uploading`, `published` or `unknown` blocks a new row unless `--again`.
- A post of a video to another Account is a row in that Account's `posts.csv`.

### stats.csv

Columns: `fetched_at,platform,handle,url,content,views,likes,comments,shares,saves`. Empty means unknown, never zero. `ralphy stats fetch` appends rows; rows are never rewritten, so a post's history is its rows.

### Content ids

`<account>/<nnn>-<slug>`. A bare `<nnn>-<slug>` or `<slug>` resolves when it is unique across `RALPHY_HOME`. `nnn` is a per-folder sequence with 3 digits.

### Writes

Atomic: write a temp file in the same directory, then `os.replace`. CSV updates happen under an exclusive `fcntl.flock` on `<file>.lock`. Media and versions are never deleted or overwritten; a regeneration gets a new name. `render.mp4` is the only file Ralphy overwrites: `ralphy render` renders a copy of the working tree under `RALPHY_CACHE_DIR/render/`, moves the result to a hidden temp file next to `render.mp4`, checks it with ffprobe (a video stream with a duration), then `os.replace`s it; a failed render leaves the previous `render.mp4` in place. `content restore` writes the working tree only after saving it as a version.

## Verbs

| Verb | Contents |
|---|---|
| `setup` | Create `RALPHY_HOME` and the config dir, write a `keys.env` template, run the doctor checks |
| `doctor` | Report tools (uv, python, bun or node, ffmpeg, Chrome), folders, which keys are present (names only) |
| `account` | `new <name>`, `list`, `show <account>`, `login <account> <platform>`, `check <account> [<platform>]`, `open <account> <platform>` |
| `content` | `new <account or inbox> "<title>" [--ref <path or url>]`, `list [--account]`, `show <id>`, `save <id> [-m note]`, `restore <id> <vN>`, `path <id>`. `restore` first saves the working tree as a new version (note `before restore of vN`; skipped when the tree already equals the latest version), then writes vN's files into the working tree and removes code files vN does not have; it never touches `media/`, `render.mp4`, mp4 files or other versions. There is no `select` |
| `render` | `render <id>`: renders the working tree to `render.mp4`, replacing the previous render (see Writes). Versions are not rendered; restore one to render it |
| `post` | `plan <id> --to <account>:<platform>[,...] [--at ISO] [--caption ...]`, `approve <post-id or --all --account a>`, `run [<post-id> or --due]`, `list [--account]`, `cancel <post-id>`, `resolve <post-id> --url <url> | --failed` (settles an `unknown` row after a manual check). `plan` posts `render.mp4`; when it is missing or stale it renders first (local and free), then checks it. `run` clones `render.mp4` to `RALPHY_CACHE_DIR/post/<post-id>.mp4`, checks the copy against the platform again and uploads that copy, so a re-render during an upload cannot change the file. `cover.jpg` (or `.jpeg`, `.png`) in the video folder is the post cover: `run` sets it on Instagram and YouTube, and it never makes the render stale. `timer on [--every 10] | off | status` (macOS) installs a LaunchAgent that runs `post run --due` |
| `stats` | `fetch <account> [--platform p]`: opens each signed-in platform profile, reads the numbers its own pages load (Instagram graphql, YouTube Studio `list_creator_videos`, TikTok `item_list`) and appends one snapshot row per video to `stats.csv`, with `content` set for the account's posts |
| `trends` | `trends --list`, `trends <niche> [--limit n]`: reads the hosted base, caches it |
| `lib` | `lib search <query> [--kind]`, `lib get <id>`: reads the hosted library, caches it |
| `tool` | `tool --list`, `tool <name> [args]`: runs `tools/<name>.py` through `uv run` |
| `panel` | `panel [--port 4777] [--no-open]`: idempotent and non-blocking. A panel counts as running when `RALPHY_CACHE_DIR/panel/server.json` names a live pid whose `/api/health` answers with that pid; then it prints the URL and opens the browser. Otherwise it starts the server as a detached child (`start_new_session=True`, stdout and stderr to `panel/server.log`), waits up to 10 s for `/api/health`, opens the browser and prints the URL. `--json`: `{"ok": true, "url", "pid", "started", "home"}`. Port 4777, or the next free port when it is busy. `panel stop` stops it; `panel --foreground` runs it in the terminal (development) |

### Panel

Content and Accounts (with Schedule), plus Trends. The grid poster and the default player use `render.mp4`; a stale render carries a quiet marker; a video without a render shows its working tree's frame at 1 s through the HyperFrames player, or a placeholder. The viewer plays the render by default; Current (the working tree) and every saved version play live through the vendored `<hyperframes-player>`; Compare plays two of them side by side with one shared play, pause and seek. The only writes are approve and cancel of planned posts (launch token in the page the server renders, `X-Ralphy-Token`, `Origin` and `Host` checks). Render, save, restore and plan are commands the person copies to the agent. Server-Sent Events refresh the card and the open viewer when `render.mp4`, `versions/`, `notes.md` or the working tree change.

## Hosted (Firebase project `ralphy-trends`, Hosting)

- Trends: `RALPHY_TRENDS_URL`, default `https://ralphy-trends.web.app/trends/v1`.
  - `index.json`: `{"updated_at", "niches": [{"slug", "name", "videos", "updated_at"}]}`.
  - `<niche>/latest.json`: `{"niche", "updated_at", "items": [{"url", "platform", "author", "title", "published_at", "views", "likes", "comments", "multiplier", "format", "hook", "thumbnail"}]}`.
- Library: `RALPHY_LIBRARY_URL`, default `https://ralphy-library.web.app/library/v1`.
  - `index.json`: `{"updated_at", "items": [{"id", "kind", "name", "category", "summary", "tags", "path", "sha256", "bytes"}]}` with `kind` one of `motion`, `video`, `prompt`; `path` is relative to the base URL.
- The hosting agent owns the exact fields; clients tolerate missing fields and an unreachable host (clear error, cached copy when present).

## Skills

`skills/<name>/SKILL.md` with only `name` and `description` in the frontmatter, optional `references/`. Every skill except the entry skill `ralphy` is named `ralphy-<job>`. At most 10:

| Skill | Job |
|---|---|
| `ralphy` | Main: folders, verbs, the loop, hard rules, which skill when. Invoked without a concrete task, or asked to show the videos: run `ralphy panel`, give the URL, then ask what to work on |
| `ralphy-trendwatch` | Find references in the hosted base or a custom niche; pick outliers; read signals |
| `ralphy-reverse` | Copy a video from a reference as exactly as possible: pull, breakdown with timecodes, rebuild in HyperFrames, original sounds allowed; ends with `content save` (v1) and `render` |
| `ralphy-remake` | Rework the copy for the Account: style lock, swapped subject, text, offer; fixes from successful signals; keep the proven timing skeleton; iterate with `render`, `content save` before risky changes, Compare in the panel, `content restore` to go back |
| `ralphy-publish` | Accounts, platforms, sign-in, plan, approval, run, captions; posts `render.mp4` |
| `ralphy-fal` | Generation through the fal hosted MCP server and direct provider APIs; model choice, cost shown first, approval |
| `ralphy-library` | Find and use components, video blocks and prompts from the hosted library |
| `ralphy-media` | The bundled tools: when to use which |
| `ralphy-setup` | Install, keys, doctor, troubleshooting |

Stats are read with `ralphy stats fetch`; reading them against references stays in `ralphy-trendwatch`.

## Tools

`tools/<name>.py`, PEP 723 inline dependencies, run by `ralphy tool <name>`. The module docstring's first line is the one-line summary shown by `ralphy tool --list`; every tool supports `--help` and `--json`. Set: `pull` (yt-dlp into `refs/<slug>/` with `source.json`), `frames` (contact sheet and keyframes), `cuts` (scene cuts), `beats` (beat grid and tempo), `transcribe` (word timings), `ocr` (on-screen text), `loudness` (LUFS, peaks), `stems` (vocals and music split), `matte` (background removal), `breakdown` (runs pull, frames, cuts, beats, transcribe and writes a timecoded `breakdown.md` skeleton), `compare` (side-by-side frames and audio offset of a render against its reference or an earlier render cloned to the cache). `ralphy tool` keeps the caller's working directory.

## Hard rules for the product

1. No paid generation and no posting without the user's explicit go; show the cost first.
2. Never delete media or versions; `render.mp4` is the only file Ralphy overwrites.
3. Start from a working reference (reverse), then remake.
4. The agent uses its own tools freely (ffmpeg, curl, yt-dlp, HyperFrames). Ralphy verbs exist only for state, posting, rendering, trends, library and the panel.
